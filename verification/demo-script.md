## 二、核心段演示（约 8～10 分钟）

| 步骤 | 操作 | 讲解要点 |
| --- | --- | --- |
| 1 | 打开首页 | 看板列表按创建时间升序；同名看板用创建时间区分；健康检查通过才进入工作区 |
| 2 | 选中「课程作业」看板 | 三列（待办/进行中/已完成）；卡片显示负责人、截止日期、逾期文字、状态文字 |
| 3 | 点「＋ 新建任务」 | 标题必填；描述 2000 字符计数；日期允许过去；负责人可“未分配”；状态可预选 |
| 4 | 保存后打开详情 | 创建时间与最后更新时间（Asia/Shanghai）；改状态按钮 → 卡片立即移到对应列，逾期标记随完成态消失 |
| 5 | 编辑（改标题、清空负责人与日期） | 五字段完整 PUT；清空有效；取消不写库 |
| 6 | 删除 | 确认框含任务标题与“不可恢复”，默认焦点在“取消”，回车不会误删；删除后焦点移到相邻卡片 |
| 7 | 双浏览器 | A 保存后 B 不会自动更新；B 点“刷新看板”读到最新数据，最后刷新时间更新 |
| 8 | 覆盖演示 | B 打开编辑表单 → A 改标题保存 → B 保存时提示“可能覆盖他人修改”：取消不写；确认后五字段等于 B 的提交（明确说明这是既定 P0 行为，不是合并） |
| 9 | 外部删除 | A 删除任务后，B 用旧表单保存 → “该任务已不存在”，刷新后任务消失，不会被 PUT 重建 |
| 10 | 失败恢复 | 停掉后端 → 点刷新：保留当前数据并标记“可能已过期”；新建表单提示成员不可用并禁用保存；恢复后端后刷新恢复正常 |
| 11 | 空态与 404 | 用空库启动（`db:init` 到新文件）→ 首页显示创建引导；直接打开不存在的看板 ID → “看板不存在”，不回落其他看板 |
| 12 | 持久化 | 重启服务（同一数据库）→ 数据仍在；按 README 备份、恢复后核对数据一致 |

窄屏（可选 30 秒）：把窗口缩到 360 px，三列横向滚动并显示「← 左右滑动查看三列 →」。

## 四、故障恢复步骤

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动即退出，提示配置无效 | `ALLOWED_HOSTS` 缺失、`PORT` 非法、`ENABLE_*` 置 1 | 按提示修正 `.env`；扩展开关必须为 0 |
| 启动失败：数据库文件不存在 | 未初始化或路径写错 | `npm run db:init`（或把 `DATABASE_PATH` 指向已初始化文件） |
| 启动失败：结构版本落后/校验和不一致 | 迁移未执行或迁移文件被改写 | 执行 `db:init`；不要修改已执行的迁移文件 |
| 页面提示“暂时无法连接服务” | 后端未启动或数据库不可读 | 启动后端 → 点“重新检查” |
| “刷新失败，数据可能已过期” | 刷新时后端不可用 | 当前数据未丢失；恢复后端后再次刷新 |
| 保存/删除失败 | 网络中断或 503（锁等待超时） | 输入与卡片会保留；恢复后重试；提示超时时先刷新查证，避免重复创建 |
| 端口被占用 | 已有实例在运行 | 关闭占用进程或改 `PORT` |
